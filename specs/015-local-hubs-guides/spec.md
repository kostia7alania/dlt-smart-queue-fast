# Feature 015: Local Discovery Hubs and Process Guides

**Status:** In Progress
**Created:** 2026-07-31

## Goal

Give search visitors an evidence-bounded entry point for the two questions the
interactive tools cannot answer on their own — *which offices near my city can I
actually try?* and *what does the licence task involve before I open the
official queue?* — using only data this repository can prove and official
destinations for everything it cannot.

## Relationship to Feature 014

Feature 014 (`specs/014-launch-trust-handoff`) is being implemented in parallel
in a second session and owns the home page, `/appointments`, the first foreigner
guide, the shared public chrome widget, and the centralized trust copy in
`shared/config/site.ts`.

Feature 015 therefore:

- adds only routes 014 does not own: `/offices`, `/offices/[city]`, `/guides`
  (index), `/guides/convert-foreign-driving-license-thailand`, and
  `/guides/renew-thai-driving-license`;
- adds the committed office-directory dataset and model that hub pages need;
- reuses 014's chrome, trust copy, and official hand-off after the branches
  merge, instead of duplicating them (see `plan.md`, "Merge Contract").

Both branches touch `apps/web/src/app/sitemap.ts`. That file is the single
expected conflict and is resolved by keeping the union of routes.

## Research Basis

Recorded in this feature's research notes (`docs/research/2026-07-31-*.md`):

- Every official DLT web property inspected on 2026-07-31 (`www.dlt.go.th`,
  `gecc.dlt.go.th/dltsmartqueue/`, `www.dlt-elearning.com`) renders through
  JavaScript and returns only a loading shell to a plain HTTP fetch. Deep
  official page text therefore cannot be quoted reliably; official URLs can be
  linked as destinations, and procedure must not be asserted as our own fact.
- `gecc.dlt.go.th/robots.txt` allows all crawlers (`User-agent: *`,
  `Disallow:`), and the upstream API host `app-gecc.theassistech.co.th` serves
  only the Cloudflare content-signals preamble with no signal set and no
  disallow rules. Nothing observed grants or restricts more than our current
  bounded read-only use.
- Procedure reported by third parties (documents, tests, fees, e-learning) is
  inconsistent between sources and changes between years, so it belongs in
  attributed, dated "reported" form only.
- The committed office capture contains 218 entries, of which 212 have a name,
  115 have `app_open = 1`, and 6 named entries have no geocode because they are
  mall/hospital sub-branches, a test site, or a placeholder (`-`). Coverage must
  be stated from the data, not rounded up.

## User Stories

### P1 — Find the offices that serve my city

As a foreigner in Bangkok, Chiang Mai, Pattaya, or Phuket, I can open one page
that lists the DLT offices associated with that area, see which of them the
booking system currently reports as open for appointments, and jump straight
into Calendar or Compare with those offices preselected.

### P1 — Understand a licence task before opening the official queue

As a first-time visitor searching for licence renewal or foreign-licence
conversion, I can read a short page that separates what this service can prove
from what only DLT can confirm, and continue either into live availability or to
the official service.

### P2 — See the limits of the coverage

As a careful visitor, I can see how many offices the dataset covers, when the
underlying capture was taken, that appointment openness comes from the upstream
`app_open` flag, and which entries are excluded and why.

### P2 — Reach the tools from any content page

As a visitor who landed on a hub or guide, I can reach Calendar, Compare, Map,
and History with the city or work option already applied, without reading
developer documentation.

## Functional Requirements

1. A committed office-directory dataset MUST be generated by a repeatable tool
   from the captured upstream office list plus the existing geocode dataset, and
   MUST preserve upstream `sit_name` strings byte-for-byte, including
   `Phuket Provincial Land Land Transport Office`,
   `Samut PrakanProvincial Land Transport Office Phra Pradaeng Branch`, and `-`.
2. The dataset MUST record its provenance (source file, capture date, generator
   command) and MUST NOT invent names, coordinates, provinces, or statuses.
3. City hubs MUST be defined by an explicit committed registry of site IDs, not
   by name substring matching at render time.
4. `/offices` MUST list every configured city hub with its office count and the
   count the upstream capture reports as open for appointments.
5. `/offices/[city]` MUST be statically exported for each configured city and
   MUST show, per office, the exact upstream name, the site ID, the
   appointment-open flag as observed, the geocode precision when present, and
   deep links into `/calendar` and `/map`.
6. Each hub MUST offer one Compare link that preselects that city's site IDs
   within the existing 8-office cap, and MUST state when the cap truncates the
   list.
7. Hub pages MUST NOT claim that an office accepts a particular applicant,
   service, or nationality, and MUST NOT present `app_open` as a guarantee of
   available appointments.
8. `/guides` MUST index the guide set; each guide MUST separate "what this
   service can show", "what only DLT can confirm", and "reported by third
   parties (dated, attributed)".
9. Guides MUST link the official destinations by their canonical HTTPS URLs and
   MUST NOT link hosts observed to serve an untrusted certificate chain.
10. New routes MUST have unique titles, descriptions, self-canonical URLs,
    sitemap entries, and internal links into the discovery tools.
11. Structured data MUST be limited to `BreadcrumbList` plus, on hub pages, an
    `ItemList` of the offices actually rendered, and MUST escape `<` before
    rendering.
12. All new UI MUST be static Server Components inside the existing FSD layers
    with the `tw:` prefix and BEM hooks, MUST add no dependency, no client
    state, no analytics, and no cookies.

## Non-Goals

- Registering domains, deploying, or touching cloud, analytics, or Search
  Console accounts.
- Asserting document requirements, test rules, fees, walk-in policy, or office
  eligibility as this project's own factual claims.
- Thai-language pages before a maintained translation workflow exists.
- New API endpoints, schema changes, live upstream fan-out at build time, or
  any change to Go business logic.
- Duplicating Feature 014's home page, `/appointments`, chrome, or trust copy.

## Success Criteria

- `node --test` covers the dataset generator, the directory model, the city
  registry, and the sitemap route list.
- A static export contains `/offices`, one page per configured city, `/guides`,
  and both new guides, each with a correct canonical and breadcrumb JSON-LD.
- Office counts rendered on hub pages equal the counts computed directly from
  the committed dataset in tests.
- Every external link on the new pages is `rel="noopener noreferrer"` and points
  at an official destination that resolved cleanly on 2026-07-31.
- Biome, TypeScript, `next build`, `git diff --check`, and the Go test suite
  pass; validation evidence is recorded in `tasks.md`.
